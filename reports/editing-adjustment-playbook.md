# 影视解说修改调整记录与未来 skill 资料

本文件保存本轮观察、修改方法和检查口径，供以后提炼成 skill。当前没有安装或发布正式 skill。案例参数可调，用户反馈、人工内容判断与机械检查分别记录；禁止把某次技术通过写成普遍剪辑规律。

## 修改案例

| 问题表现 | 原因与修改方法 | 检查方式及反馈边界 |
|---|---|---|
| 原成片平庸，15秒B更受认可 | 重新安排钩子、信息落点、人物反应与动作，使用同一口播比较；固定声音的A/B与改变混音的C分别记录 | 用户认可15秒B；正式入口重现同版本的画面与音轨，不等同整片获认可 |
| 扩展开场前半好、后半变平 | 短片节奏未自动延续到长段；按叙事转折重排后半段画面任务 | 单独记录后半反馈，不因前15秒成功跳过长段审片 |
| 全程口播，无影视原声和底乐 | 在关键情节插入完整原声，口播让位；底乐参与连续混音 | 本片有4处原声，底乐为本地合成试听音乐；用户对C2方向基本认可，未独立证明音乐审美通过 |
| 约20秒原声与口播重叠、不自然 | 对白与口播两路发言顺序拼接，仅背景音乐与发言混音；先等口播句尾落地 | 检查两路语音占用时间与实际试听；正常空拍与全静默需区别，不能见停顿就全部删掉 |
| 用错了口播录音 | C版曾使用旧整段录音；C2找回用户提供的原MP3，用来源指纹绑定且保持原速 | 来源校验加句级对齐；文件名、字幕文本相同不能证明音源正确，不重做TTS替代已有录音 |
| 原声只一句就突然切走 | 只按秒数截取会截掉回答或反应；扩展到完整问答回应，允许原声音尾延续到下一画面 | 用户指出回应太短后修订；检查完整语义、尾音和反应，不无限延长或带入无关对白 |
| 原声回应后接入口播硬，有完全静默 | 删除额外静默，较轻尾部做渐进音量衔接，底乐保持连续 | 局部静默检测与实际试听分开；本片尾部0.3秒渐进、最高+3dB是案例参数，不是默认规则 |
| 口播字幕过长，占满画面 | 改短句逐条显示，按实际口播同步；最多两行，调整字号与底部空间 | 本片每行≤12字符、1080p字号44为案例参数；实画面检查字体、脸部遮挡和阅读感，避免两套字幕叠加 |
| 标点独占第二行 | 按字符数机械换行形成孤立标点；修改结尾显示文本 | 检查实际画面，不把字数通过当作排版完成；字幕正文不改口播含义 |
| 全程硬切，缺乏镜头语言 | 保留原片真实摄影机移动、完整手势和动作落点；穿插近景、特写、双人中景、远景 | 原片有动作时不从中间截断；不要用无意义数字推拉代替真实摄影机运动，也不要求每个切点都加转场 |
| 1:07–1:40同一素材切来切去 | 源时间无重叠仍可能是同一谈话；加入求助、余陆会面、走廊告别和连续离开动作 | 局部同办公室场景30.08秒→4.48秒；按scene_id、空间、动作和信息增量审核，未证明全片重复率或最新主观质量 |
| 2:22口播半句突然跳转 | 原MP3已含残句，并非导出丢样本；先比对原录音，再让用户选择删除或补录 | 用户确认删句；移除3.32秒并同步画面/字幕。完整音轨哈希一致不能证明原录音语义完整 |
| 分段导出可能产生声音断点 | 画面可分段渲染，最终使用一条完整连续混音，避免拼每段AAC形成断点 | 比对最终音轨与完整基准的解码PCM；用完整解码验证输出，不仅看编码返回值 |

## 可复用的流程

1. **确认输入**：冻结视频、口播MP3、脚本版本及用户许可。核对原录音全文与句界，记录缺句、残句、语音和文字的差异；不把旧稿补回新录音，也不静默换TTS。
2. **定义画面任务**：每段列出人物、情节、场景、情绪、信息落点与需要保留的动作。证据镜头和中性反应镜头分开；跨场画面并置不能证明原片因果。
3. **审核候选**：冻结前3候选并逐段记录可用/不可用/待审。保留片段入出点、场景ID、机位/景别、运动、匹配理由。手选成功不回填为自动检索命中。
4. **编排长段**：按叙事推进选择镜头，检查连续窗口的场景集中、人物脸切换、动作截断和信息增量。物理去重与语义去重分开，长段不得只继承15秒快剪密度。
5. **安排声音交接**：关键原声有完整语义和反应落点；口播让位，两路讲话不默认叠加。按内容允许L-cut；保留合理呼吸，音乐、环境音和语音的音量关系要试听。
6. **排字幕**：按录音短句对齐，合理留边、不盖关键表情、避免双字幕和缺字。换行按词义而不只字符数，标点不单独占行。
7. **输出并核验**：完整解码、帧数/帧率/时长、音轨一致、句尾、字幕同步分别检查；抽查长段与所有原声接点。技术结果不能替代内容与听感判断。
8. **留下反馈和修改量**：每轮保留旧版、新版、原话反馈、原因、改动与验证；需要补录或改变完整句时由用户决定。用户已要求直接完整片时，不反复生成确认短片。

## 未来 skill 的输入与输出约定

输入应包括原片清单、冻结口播与脚本、句界/ASR对齐、top3候选、场景与动作标记、当前时间线、用户反馈、可改范围及输出规格。没有某项就明确标缺失，不伪造标注。

输出应包括可追溯的编辑计划、完整混音计划、短句字幕、完整成片、技术核验、内容待审事项与逐轮修改账本。账本建议字段为 `revision_id / issue / evidence / cause / action / affected_range / verification / user_feedback / status`；真实台词、媒体路径和精确源时间仅留本地，公开报告使用脱敏摘要。

决策分支：若原录音残缺，先确认删句或补录；若候选全部不合适，返回检索/画面需求而非强行剪入；若物理去重通过但场景仍单一，重新选择叙事素材而非继续切近景；若技术通过但用户认为后半平，检查长段信息推进与声音安排；若用户只认可短段，完整片保持待验。

## 未来 skill 的完成检查

- [ ] 每处关键语音均为完整句或获用户许可的删改，没有源录音残句被遗漏。
- [ ] 原声与口播没有非预期抢话，问答和反应不过早切走，合理呼吸与数字静默已区分。
- [ ] 长段场景变化有叙事理由，景别和动作有变化，没有把不同时间点当作不同内容。
- [ ] 字幕可读、与发言一致，无方框、双字幕、孤立标点或关键表情遮挡。
- [ ] 来源、时间线和修改记录可追溯，机械验证与用户判断分别记录。
- [ ] 最终达标有可用率的真实分子/分母，以及修改量、耗时和费用证据；未测数据保持未知。

当前这些条目是以后执行时的检查表，不表示本片所有内容已获最终验收。现阶段不能宣称技能已安装、自动剪辑已达到生产质量或完播收益已验证。
