# AGY交付方式更新：自动触发Codex审查

用户希望完成后无需手动转发或唤醒Codex。已创建本聊天的GitHub事件自动任务，监测本仓库标题以 AGY 开头的PR及PR提交更新；普通main分支push不触发。

## 今后阶段交付

1. 先读取最新任务、计划与Git状态，保留本地未提交修改。
2. 在独立任务分支完成已授权工作，逐项提交代码、必要测试和 reports/ 阶段报告；视频、字幕、凭据不入Git。
3. 报告明确 implementation_complete 或 blocked、验证证据及未验证项；可交付时状态 awaiting_review。
4. 推送任务分支并创建以main为目标的非草稿PR，标题必须以 AGY 开头，例如 AGY：阶段0修正复核 或 AGY：素材下载报告。PR描述引用对应任务和报告，列出检查结果。
5. 修正同一交付时更新已有PR分支，避免重复开PR。不要自行合并。
6. 完成后等待 reviews/ 中与该PR和最终提交对应的审查报告。审查仍不替代用户验收，不得据此自动推进下一阶段。

## 与旧指令的关系

本文件仅将尚未交付任务的“直接推送origin/main”改为“推送任务分支并开PR”，其他任务范围与验收规则不变。已推送main的历史提交不重写、不回滚，可后续按原审查任务做修正PR。

若缺少GitHub PR创建权限或工具，报告blocked及需要的操作，不擅自处理凭据。此机制目前仅确认自动任务创建成功，尚无真实PR事件完成端到端触发验证。
