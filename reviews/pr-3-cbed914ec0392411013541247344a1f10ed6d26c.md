## A：先保证不会覆盖已有工作（P1）

位置：src/vmv/runner.py 的 prepare_worktree_for_task。

根因：
- git worktree add 使用 -B；已有 task/<id> 分支时，它会重置分支到 origin/main。
- status 失败后 shutil.rmtree(..., ignore_errors=True) 会删除无法确认用途的目录。
- 非 Git 目录直接创建普通目录并当作 worktree 成功，掩盖配置错误。
- 既有 PR #2 实际分支为 task/stage0-review-fix，代码却按 id 构造 task/stage0-fixes，不能保证修正原交付。

独立实测：在 task/x 创建未发布提交，回到 main 后调用此函数，task/x SHA 被重置，函数没有报错。

具体改法：
1. TaskState 持久保存实际 head_branch 和 worktree_path；已有交付从真实 PR 获取分支，不从 task id 猜分支。
2. 先用 git worktree list --porcelain 检查实际注册路径/分支。已有有效任务工作区只核验并复用；路径异常、分支在其他工作区被占用或有冲突则 blocked，保留现场。
3. 创建全新分支才用 git worktree add -b <new_branch> <path> <base_sha>。
4. 已有分支用 git worktree add <path> <existing_branch>，禁止 -B、reset、自动 rmtree。远程已有交付先取得真实分支及 SHA，核对后附着原任务分支。
5. git status 用 --porcelain=v1，识别完整未合并状态 DD/AU/UD/UA/DU/AA/UU，不能只检查首字符 U。
6. 非 Git 根目录应报配置 blocked，不降级成普通目录。

必须测试：已有分支额外提交 SHA 不变；未知目录哨兵不被删除；冲突/分支占用不启动 CLI；主 checkout 未提交文件内容和 Git 状态不变。至少一项用真实临时 Git，不能全 mock subprocess.run。

## B：远程拉取失败必须停止派发（P1）

位置：run_once、load_queue_tasks、get_task_prompt。

根因：run_once 丢弃 fetch_remote_main 的 (success,error)，失败后继续读旧缓存或本地文件执行。load_queue_tasks/get_task_prompt 又静默回退本地。
独立实测：fetch 返回 False/offline，带 authorized=true 的本地旧队列仍启动 CLI 1 次，最后进入 awaiting_review。

具体改法：
~~~python
ok, error = self.fetch_remote_main()
if not ok:
    # 单独记录 runner 诊断；不抹掉现有 task 状态
    print(error)  # 脱敏
    return 1
~~~
成功后解析 origin/main 的具体 SHA，本周期的 queue/task/review 统一从该 SHA 读取。远程队列/任务缺失或 JSON 不合法：明确诊断并不派发；禁止静默退到用户 checkout 的旧授权。测试应 mock fetch 本身，移除生产函数中 PYTEST_CURRENT_TEST 跳过真实行为的分支，避免测试与生产执行不同规则。

必须测试：断网且有旧 ready 队列时 CLI 调用为0，既有任务状态保留；远程缺 queue/任务或 JSON 损坏不执行；远程撤销 authorized 后，本地旧授权不生效。main 目前尚无 tasks/queue.json，队列只在本 PR 分支里，不能据此宣称生产远程闭环已接通，也不要为了测试自行合并 PR。

## C：审查只认精确 PR 与当前提交（P1）

位置：find_matching_review、sync_existing_deliveries、get_pr_number_for_branch。

根因：
- 本地 reviews 目录有旧报告但没有当前报告时，提前 return None，远端新报告永远不查。
- 远端没有当前 SHA 时取 matching_files[-1]，可能用旧提交报告。
- 用正文包含 task id/SHA、或只按 PR 编号匹配，会串用其他交付。
- state=all 的 GitHub查询只拿 data[0].number，未校验 open/draft/head；拿不到 PR 仍视为交付成功。
- 首次登记主要靠本地历史文件和可能过时的 branch ref，没有核对真实当前 PR。

独立实测：本地只有旧 review 时当前远端查找返回 None；移除本地目录后，head=new 的任务错误选中了远端 pr-3-old.md。

具体改法：
1. 最简单的读取方式：构造唯一目标 reviews/pr-<number>-<40位完整sha>.md，git show <snapshot_sha>:<exact_path>。没找到就是继续等待，绝不能退到旧 SHA 或正文包含匹配。
2. 远程报告保存在 .vmv-runner/reviews/ 缓存或直接返回文本，不写用户 checkout 的 reviews/。状态记录仓库逻辑路径，别对缓存路径用 relative_to(repo_root) 猜路径。
3. 当前 PR 信息必须来自真实 GitHub响应，核对 repository、number、state=open、draft=false、head.ref 和 head.sha；已关闭只记录关闭，不启动新修复。
4. 首次登记按明确 task↔PR/实际分支映射核对现有交付，不靠正文关键词发现“完成”。GitHub读取不可用就诊断 blocked，禁止重复执行原交付。
5. CLI 退出0后仍需核对 worktree提交、远程推送提交与 PR head一致；缺 PR、缺 SHA、未推送或不一致不能进入 awaiting_review。
6. 报告结论按固定字段精确解析 pass/pass_with_notes/request_changes/blocked，不能全文搜索 pass（例如 not_pass 也含 pass）。

必须测试：本地旧报告+远端精确新报告能够取到新报告；远端只有旧 SHA 时不通过也不派发；PR编号错不匹配；CLI退出0却无真实 PR/SHA时不进入 awaiting_review；PR closed/draft时不派发。真实临时Git可用 git update-ref 设置 origin/main，不需联网。

## D：去重记录不能在成功后清空（P1）

位置：TaskState 与 request_changes 分支。

根因：用 last_error 临时保存 dispatched:<sha>，CLI返回0后又 last_error=None。没有新提交时，同一审查下次轮询会再次派发。
独立实测：CLI返回0、worktree HEAD仍为same，连续run_once两次，修正启动2次。现有测试仅预置标签后跑一次，没有测真实两轮流程。

具体改法：
- 新增独立 dispatched_reviews 字段（默认空列表，兼容旧 state.json），每个键为 PR编号:被审查SHA；last_error只存错误。
- 启动修正前在锁内先持久化该键，再启动 CLI。成功、失败、中断均不删除这个历史键。
- CLI返回0但 HEAD未变化或没有推送到同一 PR：blocked，并说明“未产生可审查的新交付”，不能清空去重记录然后循环。
- 真实新 PR head取得后更新 head_sha，等待新 head对应的新报告。
- 同一审查要重新人工核验重试须显式状态操作，不可自动无限循环。

必须测试：从没有标签的初始状态出发，第一次派发CLI退出0但HEAD不变，再跑第二轮，CLI总调用数仍为1；新HEAD的新request_changes能另派发一次；失败/重启后旧审查不重复。

## E：PID 要在进程活着时保存（P1）

位置：execute_cli_task 与 run_once 两条执行分支。

根因：Popen后先communicate等待最多600秒，函数返回后run_once才赋值st.pid并保存。整个执行期间state.json里PID是None（或上一轮旧PID），并非报告所说“实时写入”。
独立实测：在execute_cli_task执行边界读取state.json，running任务pid=None。若父runner此时崩溃，子进程可能仍写文件，下一轮无法凭该字段核对现场。

具体改法：
1. 分离启动与等待，或增加 on_started(pid) 回调：
~~~python
proc = subprocess.Popen(argv, cwd=worktree, ...)
on_started(proc.pid)  # 在communicate前：更新状态并save_state
stdout, stderr = proc.communicate(timeout=600)
~~~
2. run_once回调同时保存pid、开始时间、实际worktree、实际分支；新执行前清除旧pid。
3. 超时kill后communicate/wait回收子进程；如果CLI会产生继续写入的后代进程，记录并处理该行为，不能只假设父PID代表整个任务结束。
4. running进程还活着时不启动任何第二个写任务。确认死亡后interrupted，保留现场；现有“当轮停止、不捡起interrupted”的修正保留。
5. 重启核验实际进程身份和交付现场，PID复用不能认作原AGY任务。

必须测试：使用本地假CLI（实际短暂阻塞进程，不调用AGY），在communicate等待期间可读到其真实PID；第二实例不启动写任务；中断保留工作区且不重跑；超时后子进程被回收。用独立临时目录，不跑视频业务代码。
