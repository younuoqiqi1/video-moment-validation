## 总结

白名单、文件锁、状态文件、launchd 配置和参数数组的基础方向正确，但当前实现还不能完成“Codex 把修正意见写进 Git，Mac 自动取得并让 AGY 继续工作”的核心闭环。以下三项是阻塞问题。

## 必须修正

### P1-1：没有从 Git 获取新任务，也没有独立 worktree

实施计划要求安全 fetch `origin/main`、用 `git show` 读取远程队列和任务，并在独立 worktree 执行，不能修改用户正在编辑的 checkout。

当前 `run_once` 只读取本地 `tasks/queue.json` 和本地 `reviews/`。代码中没有 `git fetch`、远程任务读取、worktree 创建或脏工作区保护；唯一 Git 调用只是硬编码查询阶段 0 分支的 `git rev-parse`。AGY 还直接以用户仓库根目录作为 `cwd`，并带 `--dangerously-skip-permissions` 执行。

影响：

- Codex 把新审查写入远程 Git 后，本机不会自动看到；
- AGY 可能直接修改用户当前正在使用、甚至有未提交改动的工作区；
- 报告中“断网后下周期恢复继续探测”的描述没有对应实现。

修正任务：

1. 在锁内安全执行 `git fetch origin main`，失败时保留原状态并记录可诊断信息。
2. 从 `origin/main` 读取 queue、任务和 review，不自动 pull/merge/reset 用户 checkout。
3. 每个任务使用独立 worktree/分支；检测分支冲突或工作区异常时标记 blocked。
4. 增加远程不可达、远程新增授权任务、脏主工作区不变的回归测试。

### P1-2：`request_changes` 不会派给 AGY，新任务也没有 PR/SHA 绑定

`awaiting_review` 状态找到 `request_changes` 报告后只会 `continue`，不会生成修正任务、不会改变 revision，也不会再次调用 AGY。首次执行成功后仅把状态改成 `awaiting_review`，并没有记录实际 `pr_number` 和 `head_sha`，所以生产路径无法实现报告声称的“按 PR 和最终提交精准匹配”。

独立复现结果：

- 正常任务执行成功后：`status=awaiting_review, pr_number=None, head_sha=None`。
- 放入与 PR/SHA 精确匹配的 `request_changes` 审查：任务保持 `awaiting_review`，AGY 调用次数为 0。

这正是 PR #2 当前仍需要修正、但自动服务应该接续处理的场景。

修正任务：

1. 交付后从真实 Git/PR 信息登记 PR 编号与完整 head SHA；没有这些信息不能声称进入可审查状态。
2. 精确匹配同 PR、同 SHA 的 review；遇到 `request_changes` 时只派发一次该审查中的修正任务，并记录已处理 review SHA/path。
3. 修正后更新同一 PR 的新 head；旧审查不得重复执行或误判通过。
4. 增加真实状态流测试：`awaiting_review → request_changes → running → awaiting_review(new head)`。

### P1-3：异常中断后会立即盲目重复执行

计划明确要求“崩溃后标 interrupted 并核实原进程，不盲目自动重跑”。当前同一次 `run_once` 先把失联的 `running` 改成 `interrupted`，随后循环又把 `interrupted` 当作可执行状态，立即再次启动 AGY。

独立复现：预置 `running` 和死亡 PID 后运行一次，AGY 被再次调用 1 次，最终重新进入 `awaiting_review`。

这可能在旧 AGY 子进程仍存活或已留下部分代码时重复修改、提交或开 PR。

修正任务：

1. 检测到 interrupted 后本周期停止，不自动重跑。
2. 核对 worktree、Git 状态、已有提交/PR及真实子进程后，再决定恢复还是 blocked。
3. 存储实际 AGY 子进程信息；不要用 runner 自身 PID 冒充 AGY PID。
4. 增加“父进程死亡但子进程/交付可能存在”的防重复测试。

## 交付证据仍不足

- 报告展示了 launchd 安装后又执行 stop 并确认已卸载，没有“最终重新启用”的证据，因此当前不能认定后台服务正在运行。
- 未提供关闭 AGY App 后，由 launchd 调用真实 CLI 完成无副作用 probe 的结果；报告也没有把该项明确列为未验证。
- `stop_service` 忽略 `launchctl unload` 的失败返回，仍删除 plist 并返回“成功停止”。应在卸载失败时保留配置、返回失败，并补测试。
- Mac 上 20/20 pytest、launchctl PID 和 CLI 状态属于 AGY 报告证据；当前云端不能操作用户 Mac，未将这些声称当作独立实测。
