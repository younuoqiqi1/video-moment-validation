位置：src/vmv/report.py:502–514、530–542。

HTML 发布后，JSON 发布失败会尝试用备份恢复旧 HTML。但恢复的 os.replace 如果也抛出 OSError，代码直接 pass；随后“清理剩余备份”仍 unlink bak_html。结果旧 HTML 无法恢复，备份也被删除，最终只剩新生成的“通过 (All Passed)”页面。错误说明只有最初的 JSON 发布失败，没有回滚失败和恢复路径。

独立复现步骤：

- 预置 env.json = OLD_JSON，env.html = OLD_HTML。
- 允许新 HTML 的 os.replace 成功。
- JSON 发布抛 PermissionError。
- 备份 HTML 的恢复 os.replace 也抛 PermissionError。

实际结果：StageResult failed，JSON 保留 OLD_JSON，HTML 不再是 OLD_HTML 而仍含 All Passed；备份列表为空；errors 仅包含 JSON publish denied。

这仍违反已授权 R2a 的旧文件保护与部分失败如实记录要求。文件系统异常不能保证恢复一定成功，但程序必须保留可恢复的原文件并如实告知，不能在恢复失败后销毁备份。
