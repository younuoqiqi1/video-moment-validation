## R2：run_once仍忽略fetch失败（原B未完成）
当前仍是self.fetch_remote_main()而不检查返回值。load_queue严格读远端只能避免本地草稿，不能避免断网后执行缓存旧授权。
独立实测：临时Git有旧origin/main授权队列，fetch返回False/offline，CLI仍启动1次。

最小代码结构：
~~~python
ok, error = self.fetch_remote_main()
if not ok:
    record_runner_error(error)  # 脱敏诊断，保留原任务状态
    return 1
~~~
不要把“检查git存在/30秒超时”当作“调用方停止派发”。
成功后固定本轮origin/main SHA，用该SHA统一读queue/task/review。缺queue、损坏JSON或缺任务明确记录诊断，不静默空队列伪装正常。移除PYTEST_CURRENT_TEST的生产绕过分支，测试mock边界函数即可。
必测：断网+旧ready授权队列，CLI为0、原状态保留；远端撤销授权不执行本地旧授权；缺失/损坏队列可诊断。现有不可达测试没有ready任务，所以没有覆盖这个漏洞。

## R3：无有效PR仍进入awaiting_review；首次登记/修正分支仍不可靠（原C余项）
独立实测：CLI退出0，get_pr_number_for_branch=None，最终pr_number=None、status=awaiting_review。
get_pr_number_for_branch改state=open/draft过滤有进展，但只返回编号，没有核对真实PRhead与本地/远端提交；修正路径甚至不再查更新后PR。sync_existing_deliveries仍读本地review与可能过期分支ref，request_changes初次登记为blocked；仍不是当前真实交付核验。

修正步骤：
1. 查询返回PR完整元数据：number/state/draft/head.ref/head.sha；用实际PR分支，不从id猜。
2. 交付后必须有真实open非draft PR及完整SHA，且worktree HEAD、远端branch SHA、PRhead一致，才awaiting_review。
3. 缺PR、未推送、HEAD不可读或不一致时blocked，说明原因；不把CLI退出0等同交付成功。
4. 首次登记按真实当前PR核对。读不到GitHub就blocked避免重复原交付；已关闭PR不启动新审查或修复。
5. 复用精确审查读取和dispatched_reviews，不回退正文关键词或其他PR。
必测：无PR/未推送/远端head不同不可awaiting_review；closed/draft不修复；当前PR#2附着task/stage0-review-fix；首次登记现有交付不重做。

## R4：关闭App验证脚本暂不应交给用户运行
scripts/verify_offline_probe.py当前存在：
1. PASSED只检查内容包含token。独立执行同一判断片段，“WRONG PREFIX TOKEN_TEST WRONG SUFFIX”被判True，违反精确内容校验。
2. shell heredoc直接把CONTENT插JSON。独立实测包含双引号的结果使JSON无效；多行同样可能损坏。
3. 只sleep15并提示用户退出，没有确认探测时App确实关闭。App一直打开仍能写passed=true。
4. 本文件与结果只在本机/tmp，脚本完成后没有卸载/清理本次probe服务的流程。此前报告step5清理不能证明此离线脚本也会清理。
5. “等45秒查看”不足以保证完成，报告自己已有一次CLI53.14秒，不能用固定短等待假定完成。
6. argv在shell中拼接，原计划要求参数数组；AGY路径/model硬编码，未接本地核验配置。

建议直接改为Python控制器，避免继续修补shell：
- tempfile建独立目录，git init，生成随机标识；
- plistlib生成唯一probe label与Python worker参数，launchctl返回值核验；
- worker通过subprocess参数数组执行已核验argv，超时最多600秒；
- 比较read_bytes()==(f"PROBE_RESULT={token}\n").encode()，禁止包含匹配；
- json.dump写结果，记录CLI结果、App关闭证据及app_closed_verified三个独立字段；
- 通过实际宿主App的进程/bundle身份确认关闭；不能确认就not_verified，禁止只凭用户倒计时称通过。CLI进程与GUI身份区分清楚；
- 控制器等待完成并显示结果，明确超时；结束卸载本次唯一label，确认卸载成功才移除该plist，保留诊断结果；不操作其他服务；
- 先用假CLI测试正确内容、错误前后缀、双引号、多行、App未关闭、超时及清理失败，再实测Mac。让用户操作前提供已验证的一个启动命令，不让非技术用户手动排错。
